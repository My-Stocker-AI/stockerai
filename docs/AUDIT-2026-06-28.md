# StockerAI — Full Reliability Audit (2026-06-28)

Nine-domain parallel audit with adversarial verification (each finding double-checked
by an independent skeptic). 53 raw findings → **45 confirmed**, 8 false alarms rejected.
Findings are calibrated to the real environment: pickers in a garage/warehouse loading
delivery crates, often idle 1–10 minutes between items, on Android **and** iOS.

Verification discipline: each finding below was re-read against the **current** code
before being trusted. The prior fix docs (Feb 2026) describe the retired n8n engine and
do **not** protect today's Python backend — several "fixed" items regressed in the rewrite.

---

## Tier 1 — Breaks a real route. (FIXED 2026-06-28)

1. **Start-machine double-count** ✅ FIXED + PROVEN. A network retry/double-tap counted
   the displayed items twice (count jumped to 4 instead of 2), inflating machine progress
   before any pick. Root cause: the n8n→Python rewrite changed a SET to an unguarded ADD.
   Fix: idempotency guard (only pre-count on first entry to in_progress). Proven live
   (4→2, triple-retry→2, single→1) and locked by 3 regression tests
   (`tests/test_start_machine_idempotent.py`).
2. **iOS unmute didn't wake the audio engine** ✅ FIXED. After a screen-lock/idle, unmute
   showed "listening" but recorded nothing. Now resumes the suspended AudioContext first.
3. **Voice restart hardening** ✅ FIXED. Resume paths now guard against a rare early
   failure leaving voice silently hung. (The "permanently locked" framing was overstated —
   the restart already self-recovers to an error state; this is belt-and-suspenders.)

## Tier 2 — Degrades a route, recoverable (in progress)

- Voice goes silent ~15–30s on a connection blip before any error shows.
- Voice-pass server hiccup drops voice at the ~10-min mark with no cached fallback
  (directly relevant to long idle gaps).
- Done list re-renders all items on every pick → 200–500ms stutter late in a big route (Android).
- No code-splitting → whole app downloads before anything shows (slow first load).
- A command spoken right as a route finishes can replay out of order.

## Tier 3 — Security / auth architecture (calibrated)

Real, but for two trusted drivers pre-launch, **not on fire**. Becomes a must-fix before
opening to outside customers. The big one — re-enabling the database's per-user guardrails
(RLS) — was deliberately disabled to fix an infinite-loop bug, so it needs its own careful
pass, not a quick toggle. Safe quick wins (PDF size cap, hide schema-leak errors, rate
limiting, input validation) can land with Tier 4. (Key rotation deferred per owner.)

## Tier 4 — Input quirks & polish

Unsorted slot ranges ("045 to 037") · all-empty PDF creates a dead route · duplicate machine
headers create duplicate machines · no PDF upload size cap · unused param that hides a DB error.

## Rejected (false alarms the skeptics killed)

Double-submit during TTS (blocked by existing guards) · optimistic-UI desync (updates are
backend-driven only) · service-worker error fallback (correctly skips APIs) · the
already-fixed Start-Picking stale-closure (known-safe pattern) · re-render storm on retry
(by design) — among others. Documented so they're not re-investigated.
